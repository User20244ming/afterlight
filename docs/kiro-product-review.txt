## Adversarial product review — Afterlight

**1. Uniform frame extraction misses the story.** Uniform time-slice sampling produces frames that hit dead air or redundant talking, not the meaningful beats a logger marks. A contact sheet of a 40-min interview at one frame per 20 seconds yields mostly mouth-closed mid-blur frames. *Remedy:* offer three extraction modes — uniform, scene-change (diff histogram between `requestVideoFrameCallback` frames), and manual scrub-and-capture — defaulting to scene-change.

**2. IndexedDB quota collapses on real workloads.** A two-hour documentary at 1920×1080, even as JPEG thumbnails, is hundreds of MB. Browsers can evict IndexedDB under storage pressure, silently losing the entire sheet. *Remedy:* store WebP thumbnails at ≤240px, persist an explicit manifest of every blob so eviction is detected and the sheet can be regenerated from source hashes; surface a quota meter and warn before quota, not after.

**3. File relinking is a lie across sessions.** Browsers can't persist absolute file paths; `<input type=file>` gives a transient File object, and the File System Access API (the only thing that can relink) is Chrome/Edge-only and still can't guarantee a stable handle after a rename or move. The "relink original files" feature will break the moment a user reorganizes their footage folder. *Remedy:* store a content hash (e.g., first 16 MB SHA) for matching, show "source file not found — drag here to relink," and never imply automatic relink works across browser restarts without re-granting the handle.

**4. The paper edit can't be played, so it can't be validated.** Marking in/out ranges and reordering tiles produces a "cut" that exists only as a metadata list. A user who's just arranged 30 selects into a sequence has no way to watch it back — they're editing blind. *Remedy:* render a low-res proxy preview by concatenating the marked ranges via MediaRecorder on a canvas sequence, or at minimum play each selected range in order with a playhead.

**5. Exports are inert metadata, not an edit decision list.** CSV/Markdown/HTML/JSON are human-readable logs, but they can't drive an NLE. The paper edit dies at the handoff: the editor still has to re-mark everything in Premiere or DaVinci. *Remedy:* add EDL (CMX 3600) and FCPXML / DaVinci XML export carrying timecode, reel names, and in/out — that's what makes the "paper edit" actually save labor downstream.

**6. Frame extraction burns memory on long-form video.** Grabbing frames from a 4K two-hour file via canvas `drawImage` means decoding the whole thing in the renderer; a 2019 laptop will OOM around the 30-minute mark. *Remedy:* use the WebCodecs `VideoDecoder` API for seek-and-decode of specific timestamps rather than playback-based capture, and cap the working resolution at 720p for thumbnails.

**7. "Local, private, no upload" over-promises the platform.** The pitch leans hard on privacy — footage never leaves the machine — but Firefox and Safari have no File System Access API and will store imported video only as a transient blob that's gone on refresh. The privacy story is quietly Chrome/Edge-only. *Remedy:* state supported browsers explicitly; on unsupported browsers, offer to import the file into a persisted IndexedDB blob with a clear storage cost, rather than silently losing it.

**8. The paper edit is destructive with no history.** Reordering and re-trimming overwrite the previous arrangement. There's no undo, no named variants, no "compare two cuts." For a planning tool whose entire point is iterating on the order, a single live state is a trap. *Remedy:* keep a history stack for reorder/trim operations and allow saving named sheet variants so two arrangements can be compared side by side.

## Judging pitch — the value that actually lands

The contact sheet and the paper edit are not nostalgia. They are the two steps every documentary and narrative editor performs before touching a timeline — log the footage visually, mark the selects, rough the order — and no software serves them. Every existing tool jumps straight to the NLE timeline, which is the wrong instrument for that stage: too heavy, too linear, too expensive to throw away.

Afterlight targets that empty middle: a zero-install, browser-local tool that imports real footage, lays it out the way film editors always have, and lets the human do the one thing machines still can't — decide what the story is and in what order it's told. The privacy-preserving, nothing-uploaded property isn't a feature; for journalists, documentarians, and anyone with unreleased footage, it's the precondition for using the tool at all.

The differentiator that earns it a place in a real pipeline — rather than a demo you admire and never open again — is the round-trip. A paper edit that exports only to CSV or Markdown is a log. A paper edit that exports to EDL and FCPXML is labor saved: every in-point, out-point, and reel reference carries into Premiere or DaVinci untouched, so the editor's first cut starts from a real decision list instead of a blank timeline. That's the version worth judging — the one that takes a workflow people still do on paper and makes it faster, private, and portable, without pretending to be an NLE it isn't.
